## What is under test

`POST /api/v1/accounts/register/` creates a **deactivated** `User` row, issues one
`ActivationToken` row, and then sends the activation e-mail — all inside a single
request-scoped transaction. Nothing in the service commits; the session dependency
commits on success and rolls back on any exception. So when the mail transport
fails, the whole registration must vanish.

The e-mail sender is an injected interface, and the test suite substitutes an
in-memory double. When that double is configured to fail it raises
`ExternalServiceError`, which the application's single exception handler maps to
**HTTP 502**.

When `raise_on_send` is `True` every send raises
`ExternalServiceError("Fake e-mail transport is configured to fail.")` **before**
appending to `sent`, so a failed send leaves no trace in the history.

constructing your own instance. A fresh instance would not be the one the app holds.


## Scenarios

Group them in a single class `TestRegistrationRollback`, mark it
`@pytest.mark.e2e`, and give every test a docstring naming the guarantee it pins.

1. **`502` on transport failure** — with `raise_on_send = True`, posting a valid
   registration payload returns 502 and the body's `detail` is a non-empty string.
2. **No `User` row survives** — capture the total user count before the request,
   post, then assert the total is unchanged **and** that `get_user(...)` for the
   address returns `None`.
3. **No `ActivationToken` row survives** — assert the activation-token table holds
   no row for that address. Since the user is gone you cannot go through
   `tokens_for(user_id)`; count `ActivationToken` rows in the table before and
   after instead, and assert the count is unchanged.
4. **Nothing was half-written** — after a failed attempt, set
   `raise_on_send = False` and register **the same e-mail again**. It must return
   **201**, not 409, and afterwards exactly one user and one activation token exist
   for that address. This is the test that proves the rollback rather than merely
   observing an error code.
5. **The failure does not leak transport configuration** — the 502 body must not
   contain the SMTP host, the port, the user or the password, and must not contain
   the substrings `"smtp"` (case-insensitive) or `"aiosmtplib"`.
6. **The double recorded nothing** — after the failed attempt
   `fake_email_sender.sent` is empty, which proves the send aborted before
   composing a message.

Write each scenario as its own test method. Two of them need a failed attempt
followed by a second request; do not merge them into one method to save typing.
