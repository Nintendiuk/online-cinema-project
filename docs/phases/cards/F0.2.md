### FILE 1 — `docker-compose.yml`

Exactly seven services, no more:

| Service | Requirements |
|---|---|
| `db` | `postgres:16-alpine`; credentials from `.env`; healthcheck using `pg_isready` against the configured user and database; named volume for `/var/lib/postgresql/data` |
| `redis` | `redis:7-alpine`; healthcheck using `redis-cli ping` |
| `minio` | `minio/minio`; runs `server /data` with the console on port 9001; API port 9000 and console port 9001 published; root credentials taken from `S3_ACCESS_KEY` / `S3_SECRET_KEY`; healthcheck against `/minio/health/live`; named volume for `/data` |
| `mailhog` | `mailhog/mailhog`; publishes 1025 (SMTP) and 8025 (web UI) |
| `web` | built from `docker/web/Dockerfile`; publishes 8000; runs the entrypoint (migrations, then uvicorn with reload) |
| `celery-worker` | same build as `web`; command runs a Celery worker for `src.core.celery_app` with the `celery_app` instance, log level info; does not run migrations |
| `celery-beat` | same build as `web`; command runs celery-beat for the same app; does not run migrations |

Additional requirements:

- `web`, `celery-worker` and `celery-beat` share one build context and one Dockerfile; they differ only by `command`.
- `web`, `celery-worker`, `celery-beat` declare `depends_on` on `db` and `redis` with `condition: service_healthy`.
- Every application service uses `env_file: .env`.
- The source tree is bind-mounted into the application containers so that code changes are picked up without rebuilding (dev hot reload).
- Use named volumes for Postgres and MinIO data; declare them in a top-level `volumes:` section.
- Do not include a `version:` key (it is obsolete in current Compose).
- Give healthchecks sensible `interval`, `timeout` and `retries` values.
- Do not add nginx, pgadmin, flower, or any other service.

### FILE 2 — `docker/web/Dockerfile`

Multi-stage build.

**Stage `builder`** — base `python:3.12-slim`. Installs Poetry pinned to a version that still ships the export command (`poetry==1.8.3`), copies `pyproject.toml` and `poetry.lock`, and exports the `main` dependency group to a `requirements.txt` without hashes.

**Final stage** — base `python:3.12-slim`:

- Copies only `requirements.txt` from `builder` and installs it with pip, no cache. Poetry must not exist in the final image.
- Sets `PYTHONDONTWRITEBYTECODE=1`, `PYTHONUNBUFFERED=1`, `PYTHONPATH=/app`.
- Working directory `/app`.
- Copies the project source and `docker/entrypoint.sh`; makes the entrypoint executable.
- Creates an unprivileged user and group (for example `appuser`), makes it the owner of `/app`, and switches to it with `USER` before the entrypoint. The container must not run as root.
- Declares the entrypoint script as `ENTRYPOINT`.
- Install no build toolchain in the final stage unless a wheel genuinely requires it; keep the image slim.

### FILE 3 — `docker/entrypoint.sh`

POSIX shell script, starting with a shebang and `set -e`:

1. Waits in a loop until the Postgres TCP port accepts connections, reading host and port from `POSTGRES_HOST` and `POSTGRES_PORT`. The final image has no `psql` client, so probe the socket with a short Python one-liner rather than `pg_isready`. Sleep one second between attempts and log each attempt.
2. Runs `alembic upgrade head`.
3. Starts uvicorn on `0.0.0.0:8000` using the ASGI factory `src.main:create_app` (factory mode) with reload enabled for development. Use `exec` so uvicorn becomes PID 1 and receives signals.
