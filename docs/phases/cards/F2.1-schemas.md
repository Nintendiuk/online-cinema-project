### Email normalisation — get this exactly right

Every schema that has an `email` field must normalise it **before** `EmailStr` parses it,
so that `"  User@Mail.COM "` is accepted and becomes `"user@mail.com"`. That means a
**before**-mode validator, not an after-mode one:

```python
@field_validator("email", mode="before")
@classmethod
def _normalize_email(cls, value: Any) -> Any:
    """Trim and lowercase the address before EmailStr parses it."""
    if isinstance(value, str):
        return normalize_email(value)
    return value
```

Non-string input is passed through untouched so that Pydantic reports the correct
type error rather than an `AttributeError`. Import `Any` from `typing`.

Three schemas need this validator. Do **not** copy the method body four times by hand
into unrelated classes — define the email-carrying behaviour once in a small private
base class (for example `_EmailNormalizingSchema(BaseModel)`) and have the three request
schemas inherit from it. The response schema does not need it. Note that each subclass
still declares its own `model_config`; make sure `extra="forbid"` survives inheritance.
