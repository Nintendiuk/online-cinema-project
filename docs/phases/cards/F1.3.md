### FILE — `tests/integration/test_accounts_models.py`

Every test is `async def`, carries `@pytest.mark.integration`, takes `db_session: AsyncSession`, and is annotated `-> None`. Persist with `db_session.add(...)` / `await db_session.flush()`; never `commit()`. Expected-failure tests use `with pytest.raises(IntegrityError):` around `await db_session.flush()`, followed by `await db_session.rollback()` so the session survives.

Give each test a docstring naming the invariant it protects. Keep e-mail addresses unique within a test by hand (`"a@example.com"`, `"b@example.com"`, …) and token strings unique likewise.

Write a small module-level helper if it removes real duplication — for example one that creates and flushes a group plus a user and returns the user — but no more than two such helpers, and both fully annotated.

Cover exactly these scenarios, grouped by `class Test...` containers in this order:

**User groups**

1. All three `UserGroupEnum` members can be inserted as groups.
2. A second group with the same `name` → `IntegrityError`.
3. `name` round-trips: after flush and refresh, the attribute is a `UserGroupEnum` member, not a raw string.

**User**

4. A user created against an existing group persists and receives an `id`.
5. `is_active` defaults to `False` when not passed.
6. `created_at` and `updated_at` are populated automatically and both have `tzinfo is not None`.
7. A duplicate `email` → `IntegrityError`.
8. `group_id=None` → `IntegrityError`.
9. Deleting a group that still has users → `IntegrityError` (the `RESTRICT` rule). Issue this delete as a Core statement — `await db_session.execute(delete(UserGroup).where(UserGroup.id == group.id))` — so the database constraint is what fires, rather than the ORM nulling the foreign key first.

**Profile**

10. One profile per user is created and linked back to the user.
11. A second profile for the same `user_id` → `IntegrityError`.
12. Every profile field is optional: a profile holding only `user_id` persists.
13. `gender` accepts both `GenderEnum` members and reads back as the enum.

**Tokens**

14. `ActivationToken`, `PasswordResetToken` and `RefreshToken` can each be created for a user.
15. A second `ActivationToken` for the same user → `IntegrityError`.
16. A second `PasswordResetToken` for the same user → `IntegrityError`.
17. **Two** `RefreshToken` rows for the same user persist successfully.
18. A duplicate `token` value → `IntegrityError`.
19. `expires_at` reads back timezone-aware.
20. `is_expired()` returns `True` for a past `expires_at` and `False` for a future one.

**Cascades**

21. Deleting a user removes the profile and all three token kinds. Delete with a Core statement, then `db_session.expunge_all()`, then assert with `select(func.count()).select_from(...)` per child table that nothing remains.
22. Deleting a user leaves its `UserGroup` in place.

All datetimes are built with `datetime.now(UTC)` plus/minus a `timedelta`; never `datetime.utcnow()` and never a naive datetime.
