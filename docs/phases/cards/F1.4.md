### FILE 1 — `tests/factories/accounts.py`

Plain async builder functions — **not** `factory_boy`, which cannot drive an `AsyncSession`. These exact signatures, unchanged:

```python
async def create_group(
    session: AsyncSession, name: UserGroupEnum = UserGroupEnum.USER
) -> UserGroup: ...


async def create_user(
    session: AsyncSession,
    *,
    email: str | None = None,
    password_hash: str = "hashed",
    is_active: bool = True,
    group: UserGroup | None = None,
) -> User: ...


async def create_profile(
    session: AsyncSession, user: User, **overrides: Any
) -> UserProfile: ...


async def create_activation_token(
    session: AsyncSession, user: User, *, expires_in_hours: int = 24
) -> ActivationToken: ...


async def create_password_reset_token(
    session: AsyncSession, user: User, *, expires_in_minutes: int = 30
) -> PasswordResetToken: ...


async def create_refresh_token(
    session: AsyncSession, user: User, *, expires_in_days: int = 7
) -> RefreshToken: ...
```

Rules that apply to every function:

- Build the object, `session.add(...)` it, `await session.flush()`, and return it with `id` populated.
- **Never call `session.commit()`.** The test suite runs each test inside a transaction that is rolled back; a commit inside a factory destroys that isolation.
- Full annotations, English docstring, no `print`, no logging.

Function-specific rules:

- `create_group` is get-or-create: look the group up by `name` with `select(...)` first and return the existing row if present, since `name` is unique. Only insert when the lookup misses.
- `create_user` with `email=None` generates a unique address. Use a module-level counter combined with a random component (or `faker`) so that repeated calls inside one test never collide. `group=None` means: get-or-create the `UserGroupEnum.USER` group by calling `create_group`, do not duplicate that logic.
- `create_profile` starts from a defaults dictionary — `first_name`, `last_name`, `gender` (`GenderEnum.MAN`), `date_of_birth`, `info` — and applies `**overrides` on top of it, so any caller-supplied key wins. `user_id` comes from the passed `user` and cannot be overridden.
- The three token factories generate the token string with `secrets.token_urlsafe(32)` and compute `expires_at` as `datetime.now(UTC)` plus the corresponding `timedelta`. No naive datetimes, no `datetime.utcnow()`.

Keep the module under 150 lines; if the defaults dictionary in `create_profile` grows, keep it inside the function rather than adding a helper.
