Marker: `integration`. Three tests:

1. **`get_session` yields a usable session.** Drive the async generator directly: get it from `get_session()`, advance it once to obtain the session, run `SELECT 1`, assert `scalar_one()` equals `1`, then close the generator so its teardown runs (`aclose()`). 2. and 3. **Rollback isolation — two near-identical tests.** Each one, using the `db_session` fixture:
   - creates a table with `CREATE TABLE isolation_probe (id INTEGER PRIMARY KEY, tag VARCHAR(50) UNIQUE NOT NULL)`,
   - inserts the row `(1, 'duplicate-probe')`,
   - asserts that exactly one row with that tag exists.

   The two tests must use the *same* table name and the *same* unique value. Both passing proves each test's transaction is rolled back; if isolation were broken, the second would fail on the duplicate table or the unique constraint. Give them distinct function names and note the intent in their docstrings.
